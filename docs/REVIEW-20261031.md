## 一、总体结论

平台骨架成熟度高于平均水平：JWT 校验、身份头剥离、刷新轮换防重放、PHI 加密/脱敏/审计、
迁移 Hook、探针分组、外部 Secret fail-closed 等核心机制实现扎实且有实测背书。
但本次评测发现 **12 项上线前必须修复（MUST-FIX）**，集中在四类：

1. **密钥治理**（PHI 密钥默认值入库、dev 弱密钥、JWT_SECRET 仅告警）；
2. **入口暴露面**（/actuator 整段免鉴权 + gateway 端点泄露路由、XFF 伪造使 IP 限速失效）；
3. **告警/灰度闭环断裂**（job 正则永不匹配、release 标签不匹配、无 Alertmanager 路由、
   灰度分析查询无服务过滤、SNAPSHOT 镜像进 staging/prod）；
4. **数据正确性**（患者合并竞态成环、限速查询全表扫描、类型转换异常 500）。

## 二、必须修改 MUST-FIX（上线阻断项）

### M1. PHI 加密密钥与查重盐存在公开默认值
- 位置：[empi application.yml:41-42](../platform/empi/src/main/resources/application.yml)、`crypto/FieldCipher.java:40`（已实证复核）
- 问题：`EMPI_FIELD_KEY` / `EMPI_HASH_SALT` 在配置文件留有默认值。环境未注入时 PHI 等于用公开密钥加密；
  哈希查重盐为固定字符串，身份证结构化、手机号 10^10 可枚举，加盐形同虚设。
- 建议：默认值置空 + 启动 fail-fast（缺密钥拒绝启动）；密钥走 KMS/外部 Secret；盐与密钥分离保管。

### M2. 网关 /actuator/** 整段免鉴权，且暴露 gateway 端点
- 位置：gateway `application.yml:58,85`（`include: gateway` + 白名单 `/actuator/**`）、`GatewayAuthProperties.java:26`
- 问题：未认证可读 `/actuator/gateway` 拿到全部路由定义与 auth/empi/ai-core 内网地址；prometheus/info 同样裸奔。
  Ingress 未外露 actuator，但集群内任意可达 Pod（含 monitoring 命名空间）均可访问。
- 建议：白名单收窄为 `/actuator/health/liveness|readiness`；exposure 移除 `gateway`；
  管理端点独立 management port，NetworkPolicy 仅对该端口放行监控。

### M3. X-Forwarded-For 可伪造，IP 限速失效、审计/会话 IP 可投毒
- 位置：[AuthController.java:112-121](../platform/auth/src/main/java/com/medassist/auth/web/AuthController.java)（取 XFF 首段）、`TokenRepository` login_attempt/client_ip、`AuthService` 审计
- 问题：SCG 对 XFF 是**追加**而非覆盖，客户端自带首段即可自选来源 IP——30 次/5min 的 IP 维度完全失效，
  且审计与 `/sessions` 的 client_ip 字段被污染。账号维度（5 次/5min）不受影响，仍是主防线。
- 建议：由可信层（Ingress/网关）计算真实源 IP 后经可信头下发；auth 不读客户端提交的 XFF；
  保留既有注释中"IP 仅辅助"的定位并文档化。

### M4. 撤销名单启动窗口 fail-open
- 位置：[TokenRevocationCache.java:47-61](../platform/gateway/src/main/java/com/medassist/gateway/security/TokenRevocationCache.java)
- 问题：启动后 5s 延迟 + 15s 周期内撤销名单为空即放行——已登出/被盗 jti 在窗口内可通过；
  auth 宕机期间新撤销不可见。
- 建议：启动阻塞式首拉（首同步完成前对保护路径 fail-closed）；连续同步失败超阈值告警。

### M5. 患者合并竞态可产生循环指针；MERGED 档案仍可 reveal
- 位置：[PatientService.java:150-165](../platform/empi/src/main/java/com/medassist/empi/service/PatientService.java)、`:85-92`、`PatientRepository.markMerged`
- 问题：A→B 与 B→A 并发时 CAS 前的 `to.active()` 预检均通过，两条 markMerged 各自成功 →
  `merged_into` 互相成环、无有效档案；链式合并亦无传递解析。合并后源档案（MERGED）仍可 reveal 读旧 PHI。
- 建议：事务内按 id 排序 `SELECT FOR UPDATE` 两行后再校验；markMerged 子查询确认目标仍 ACTIVE；
  源档案 detail 拒绝 reveal。

### M6. 登录限速查询不走索引，每次登录全表扫描
- 位置：[TokenRepository.java:186](../platform/auth/src/main/java/com/medassist/auth/repo/TokenRepository.java) vs [V4__auth_tokens.sql:49-50](../platform/auth/src/main/resources/db/migration/auth/V4__auth_tokens.sql)
- 问题：查询 `lower(username)=lower(?)` 无法命中 `(username, ts DESC)` 索引；login_attempt 保留 30 天，
  被刷场景行数巨大，放大登录延迟与 DB 压力。
- 建议：函数索引 `(lower(username), ts DESC)`，或写入统一小写后等值查询。

### M7. 类型转换/报文异常统一返回 500（已实际复现）
- 位置：auth 与 empi 两份 `GlobalExceptionHandler`（均只处理 BusinessException 与 MethodArgumentNotValidException）
- 问题：`reveal=abc`、非法 UUID 路径变量、`from=2026` 等客户端输入错误全部落入兜底 500
  （本次容器联调已实测复现"Invalid UUID string: =true"→500）。500 率虚高污染告警，集成方难排障。
- 建议：补映射 `MethodArgumentTypeMismatchException` / `HttpMessageNotReadableException` /
  `MissingServletRequestParameterException` / `DataIntegrityViolationException(→409)` → 400/409，并补测试。

### M8. 医疗合规关键路径零测试
- 位置：`platform/auth/src/test`（仅 4 个纯单元类）；empi、common 无 src/test
- 问题：完全无测试覆盖：登录/刷新/登出全流程、TokenRepository 轮换 CAS 原子性（防重放核心）、
  最后一个 ADMIN 保护、PHI 脱敏与 reveal 强制审计、LoginThrottle、AuditRepository UNION SQL、
  异常映射、Sentinel 规则加载、撤销缓存同步。这些恰是合规验收项。
- 建议：优先补认证全流程（含并发刷新重放）、ADMIN 锁死保护、PHI 脱敏/审计、异常映射、限速窗口。

### M9. SNAPSHOT 镜像 tag 进 staging/prod
- 位置：[values.yaml](../deploy/helm/medassist-platform/values.yaml)（三服务默认 `0.1.0-SNAPSHOT`）、values-staging 无覆盖、prod 兜底同为 SNAPSHOT
- 问题：staging 与 helm 直装 prod 实际跑 SNAPSHOT；配合 `IfNotPresent`，同 tag 重推不更新——发布不可追溯。
- 建议：staging/prod values 锁定不可变 tag（或 CI 参数注入）；SNAPSHOT 仅限 dev。

### M10. 灰度判定失真：分析查询无服务过滤 + Rollout/HPA 冲突无强制防护
- 位置：[values.yaml:347-350](../deploy/helm/medassist-platform/values.yaml)、[analysis.yaml](../deploy/helm/medassist-platform/templates/analysis.yaml)、`_helpers.tpl`（canaryStrategy）、Argo Application ignoreDifferences
- 问题：AnalysisTemplate 查询为全集群聚合，未按 job/service/rollout 过滤——canary 1 副本的 5xx 被稳定副本
  稀释，灰度形同虚设；`setCanaryScale` 与 HPA 拉扯仅靠 README 口头约定，模板无 fail-fast；
  ignoreDifferences 只配了 Deployment，开启 Rollout 后 HPA 扩缩会被 selfHeal 拉回。
- 建议：查询按组件注入 `job=~"<component>.*"`（ServiceMonitor 补 jobLabel）；autoscaling.enabled 时
  模板 required 阻断 setCanaryScale；三环境 Application 增加 `argoproj.io/Rollout /spec/replicas` 忽略。

### M11. 告警链路三处断点（当前规则大概率一条都不生效）
- 位置：[medassist-alerts.yaml](../deploy/observability/alerts/medassist-alerts.yaml)、[servicemonitor.yaml](../deploy/helm/medassist-platform/templates/servicemonitor.yaml)、[values-prod.yaml:112](../deploy/helm/medassist-platform/values-prod.yaml)（已实证复核）
  1) `job=~".*gateway.*"` 永不匹配——ServiceMonitor 为单一共享 job，实际 job 名形如
     `serviceMonitor/<ns>/medassist-medassist-platform-java/0`；5xx/P99 两条告警永远无数据；
  2) PrometheusRule 标签 `release: prometheus` ≠ prod 抓取栈 `release: kube-prometheus-stack` → 规则整体不被加载；
  3) 全仓库无 Alertmanager route/receiver——告警"产生但不送达"。
- 建议：改用 `service` 标签匹配或按组件拆 ServiceMonitor；统一 release 标签并验证 ruleSelector；
  补 Alertmanager 路由（severity 分流、值班接收、抑制规则）。

### M12. trace↔log 关联断裂，纠纷举证链路缺一环
- 位置：[promtail-config.yaml:39-40](../deploy/observability/loki/promtail-config.yaml)（pipeline 仅 `docker:{}`）；平台无 logback 配置、日志无 traceId
- 问题：Loki 与 SkyWalking 无法互跳；README §6.1 把 trace 定位为"审计与纠纷举证依据"，
  但出事后从日志找不到链路、从链路找不到日志。
- 建议：Java 接入 `apm-toolkit-logback` 输出 %tid（MDC），Python 输出 sw trace id；
  promtail 增加 trace_id 提取 stage；Loki 标签与 SW 服务名对齐。

## 三、应当修改 SHOULD-FIX（上线后第一批）

**安全**
- S1. JWT_SECRET 默认值仅 WARN：prod/显式生产 profile 检测到 dev 默认密钥直接拒启（gateway/auth 两处）。
- S2. monitoring 命名空间可直连 auth 伪造身份头：auth 无自身鉴权全信 X-* 头 → 管理端点独立端口 + NP 收紧。
- S3. PBKDF2 迭代上限 10,000,000 过宽（单次验证可耗数秒 CPU，叠加 M3 可放大为登录 DoS）→ 收紧至 ≤1M。
- S4. dev 弱密钥明文入库 + jwtSecret 长度无模板校验 → 本地 .env/随机生成；secret.yaml 加 fail 校验。

**数据**
- S5. 刷新轮换 revoke+insert 非原子（无事务）：中途失败=用户被登出（无重放窗口，属可用性）→ 包单事务。
- S6. 短证件号（9~12 位）脱敏保留前 4 后 4 泄露比例过高；crosswalk 外部病历号明文仅需 read → 长度自适应 + 默认遮蔽。
- S7. AuditRepository：分页无决胜列（ts 相同漂移）、count+search 每页两遍全量、detail::text 物化、两表无 ts 索引 → 加决胜列/ts 索引、keyset 分页。
- S8. auth/empi change_log 无保留期与分区 → 按月分区 + 归档策略。
- S9. 生产关闭 baseline-on-migrate（掩盖 schema 漂移）。

**部署**
- S10. 无 preStop / server.shutdown: graceful：SIGTERM 即断连 + SCG LB 缓存 ~35s → 滚动/灰度期 5xx。
- S11. ai-core /readyz 为静态常量（PG/Milvus 故障仍收流量）；gateway readiness 不含下游 → readiness 做依赖检查。
- S12. NetworkPolicy 仅 Ingress，egress 全放行（PHI 平台出站不设限）→ Java/ai-core egress 白名单。
- S13. prod ai-core 单副本且 PDB 关闭 → ≥2 副本 + 模型 PVC ReadOnlyMany + PDB。

**可观测**
- S14. OAP 明细 TTL 3 天 vs 医疗审计举证（通常 ≥6 个月）→ 调大 TTL 或周期导出归档。
- S15. OAP/UI 无认证（K8s 形态无清单/NP）→ OAP authentication token + observability NP + UI 前置认证。
- S16. Promtail positions 落 /tmp 无持久卷 → 重启重复采集；挂专用 volume。

**代码**
- S17. 两份 GlobalExceptionHandler 复制漂移（empi 缺 429 映射；Retry-After 硬编码 300 与可配置 window 脱节）→ 抽 common 单点。
- S18. TokenRevocationCache 无容量保护（auth 长期故障时无界增长）→ 惰性清理/定时 prune + 阈值告警。
- S19. REFRESH_REPLAY 审计可被重放刷库（白名单路径无限频）→ 打点 + 限频 + 审计去重。
- S20. Sentinel 规则加载失败静默 fail-open（空规则/非法 QPS 仅 info）→ warn + 指标。
- S21. 撤销名单增量拉取热路径带全表 DELETE → 清理移入 TokenMaintenanceJob。

## 四、优化建议 OPTIMIZATION

- O1. BCrypt 强度显式参数化（医疗高敏建议 cost=12，按硬件压测）。
- O2. 信任边界收敛计划：`/api/v1/**` 与 aiCore Ingress `/` 整段直连不受身份头体系保护 → 明确收敛时间点。
- O3. `/actuator` 不在 Sentinel 限流资源内（与 M2 一并收敛）。
- O4. PHI 密文头加 keyId（当前仅 `iv||ct`），为密钥轮换铺路；IV 逼近 2^32 生日界加监控。
- O5. 并发建档撞唯一索引返回 500 → 映射 409（并入 M7 异常映射）。
- O6. FieldCipher.decrypt 静默吞错返回 null → 先告警再降级。
- O7. Dockerfile：基础镜像 digest pin；补 HEALTHCHECK；`go-offline || true` 吞掉解析失败。
- O8. HPA 仅 CPU：gateway 叠加 QPS/Sentinel 自定义指标；aiCore 补 behavior。
- O9. Ingress TLS 无模板护栏（prod 靠自觉）；副本级灰度实际是 1/N 流量 → required tls + nginx canary annotation 做真实流量切分。
- O10. Loki 生产化：memberlist + 3 副本 + 对象存储；ingestion_rate_mb=8 对日志突增的评估。
- O11. 全量采样(-1) + HPA maxReplicas=10 时 OAP 容量无基线 → 压测定容、设采样保险丝、OAP 资源限制。
- O12. BusinessException 补 serialVersionUID（消除构建告警）。
- O13. audit() 三份近似实现 + 20+ action 魔法字符串 → 抽 common AuditWriter + AuditActions 常量（防查询拼错静默空结果）。
- O14. 异常日志丢堆栈（仅 e.getMessage）→ 首次失败打全栈。
- O15. fastjson 传递依赖 exclusion（全仓无直接使用）；Permissions 403 文案中文化（医护禁技术术语）；启用 jacoco。

## 五、已核验通过项（正面确认）

- JWT：HS256 算法固定、iss/exp 校验、<32B 密钥拒启；身份头剥离在 -100 最早执行（HttpHeaders 大小写不敏感覆盖变体）。
- 会话：`/sessions` DELETE 严格 user_id+id 双条件，跨账号 404。
- 审计内容：登录/重置不落密码与令牌明文；refresh 轮换 CAS 无重放窗口（失败仅是可用性问题）。
- 密码：PBKDF2 恒定时间比较、升级 CAS 正确；BCrypt 无竞态。
- 加密实现：AES-GCM 随机 96bit IV + 128bit tag 正确；加密列不可比较、等值查重走加盐哈希——设计正确（错在默认值，见 M1）。
- Helm：`required` 强制外部 Secret fail-closed；迁移 Hook 三环境一致、Job 参数完备；requests/limits/PDB/MaxRAMPercentage=75 在位；容器非 root(uid 10001)。
- 指标命名：`medassist.auth.login` → `medassist_auth_login_total` 核对成立；jvm/http 指标在当前版本可用；optionalPlugins 复制逻辑容错正确；SW v4x 插件 witness 告警已证实无害。
