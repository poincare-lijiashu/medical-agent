## 0. 执行摘要

### 0.1 结论

当前系统是**功能覆盖较完整的可试点系统**，不是可直接生产上线的商用系统。

- 业务功能覆盖约 **75%**；
- 工程与质量体系约 **60%**；
- 集成交付与合规资质约 **30%**；
- **综合商用就绪度约 55%–60%**。

本轮（§257）已补上"集成消息台账 + HL7 MLLP 投递"，解决"消息静默丢失、无法对账"的地基问题；
§258 又补上"入站幂等 + 集成指标/告警 + 运维页面"，集成维度从约 30% 提升到约 40%。

### 0.2 "100%" 的可验收定义

软件不存在抽象的"功能 100%"。本计划把 100% 定义为：

> **G1–G8 八道商用门槛全部通过，且每个能力域达到"主流基线（Parity）"；
> 同时在 3 个以上方向形成可演示、可验证的"超越项（Differentiator）"，
> 并建立持续改进机制（SLO、缺陷逃逸、临床验证、合规复审）。**

八道门槛：

| Gate | 名称 | 通过标准（摘要） |
|---|---|---|
| G1 | 临床业务闭环 | 医嘱、用药、输血、手术、检验检查、护理、交班全部可追溯闭环；对标电子病历 6 级 |
| G2 | 集成与互操作 | HL7 v2 / FHIR R4 / DICOM / CA 全部落地；对标互联互通四级甲等，冲刺五级乙等 |
| G3 | 医保与费用 | 医保 CHS 接口、目录映射、DRG/DIP 2.0 分组、日结月结与对账全部可验收 |
| G4 | 数据治理 | 主数据/术语/字典映射、历史迁移、数据质量与口径治理可审计 |
| G5 | 安全与合规 | 等保三级技术项、密评、ISO 27799 对齐、CA/时间戳、审计防篡改、灾备演练 |
| G6 | 可靠性与性能 | SLO 达标（可用性、时延、错误率）、压测基线、容灾 RTO/RPO、混沌演练 |
| G7 | 交付与运营 | 实施方法论、迁移工具、培训认证、SLA/工单/值班、版本与补丁机制 |
| G8 | AI 验证与治理 | 临床验证方案、模型/提示词版本与回滚、漂移监测、误报闭环；如按 SaMD 则补齐 IEC 62304/ISO 14971 |

### 0.3 三条主线

1. **合规与安全主线**：等保三级 + 密评 + CA/时间戳 + 审计防篡改 + 灾备；
2. **集成与数据主线**：HIS/LIS/PACS/医保/CA 真实接口 + 主数据 + 历史迁移 + 对账；
3. **临床闭环与质量主线**：电子病历 6 级要求的全流程闭环 + 2025 版核心制度监测指标。

## 2. 目标定义：什么叫"100%"

### 2.1 分层目标

| 层级 | 定义 | 验收方式 |
|---|---|---|
| Parity（主流基线） | 与国内三级医院主流系统、HIMSS Stage 6 的核心能力对齐 | 逐项打分表 + 真实接口联调 + 院内试点 |
| Differentiator（超越项） | 主流系统普遍较弱或未做好的能力 | 可演示 + 可量化 + 客户访谈验证 |
| Compliance（合规基线） | 等保三级、电子病历 6 级、互联互通、医保接口 | 第三方测评 / 官方评审 / 医保验收 |

### 2.2 计划中的超越项（Differentiator）

1. **AI 质控三轨 + 证据溯源 + HITL**：规则引擎、LLM 内涵质控、ICD/危急值三轨并行，输出可追溯；
2. **交班风险清单 + 待办事项闭环**：不是"写过了"，而是"逐条交接、逐条闭环"；
3. **集成消息台账 + 退避重试 + DEAD + 对账**：把"接口失败"从日志变成可运营的台账；
4. **全链路数据范围与 PHI 保护**：院区/科室下推 SQL、PHI 脱敏、追加式审计；
5. **开放 FHIR + Agent 生态**：对外提供标准资源与工具化 Agent，形成平台型差异。

> 超越项必须在 G1–G8 达标后仍成立；不能用"亮点功能"掩盖合规与集成缺口。

## 4. 分阶段路线图（按依赖排序，不设日历承诺）

### Phase 0：稳定与合规基线（Gate 0）

**目标**：把"能跑"变成"可重复、可观测、可恢复"。

- 交付：SLO 初版、备份恢复演练、密钥与配置基线、CI 门禁、依赖与镜像扫描、Runbook；
- 退出标准：核心服务 7×24 稳定；备份恢复实测通过；高危漏洞 0；发布可回滚。

### Phase 1：集成最小闭环（G2 起步）

**目标**：打通一条真实院内闭环（患者-就诊-医嘱-收费-回传）。

- 交付：HL7 v2 全场景、FHIR R4 适配、入站幂等、集成运维看板、CA 签名 PoC；
- 退出标准：与 1 家医院测试环境联调通过；消息成功率 ≥99.9%；对账差异可定位。

### Phase 2：临床深度与质量指标（G1 起步）

**目标**：对标电子病历 6 级的"全流程闭环 + 决策支持"。

- 交付：医嘱/用药/输血/手术/检验检查/护理闭环；核心制度 35 项监测指标；
- 退出标准：闭环率 ≥98%；危急值 5 分钟处置 ≥95%；手术核查 100%。

### Phase 3：规模与高可用（G6）

- 交付：压测基线、容量模型、灰度/回滚、混沌演练、数据库治理；
- 退出标准：峰值 2 倍余量；RTO ≤30 分钟、RPO ≤5 分钟；错误预算策略生效。

### Phase 4：验证与认证（G5、G1/G2 评审）

- 交付：等保三级测评、密评、电子病历 6 级申报、互联互通四级甲等/五级乙等申报、ISO 27799 对齐；
- 退出标准：第三方测评/评审通过；整改闭环 100%。

### Phase 5：商业化与生态（G7、G8、W9）

- 交付：实施方法论、培训认证、SLA/工单、多租户、开放平台、AI 临床验证；
- 退出标准：可复制交付 2 家以上；SLA 达标；AI 验证报告可对外。
