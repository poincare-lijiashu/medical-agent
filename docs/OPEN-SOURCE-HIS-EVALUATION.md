# 开源 HIS 选型评估（三甲目标 · 2026-10-31）

> 决策前提（用户已确认）：**质量优先于速度**；GPL 走"源码随院内交付"；立即启动评估。
> 调研方式：4 路并行检索（国内开源 / 国际开源 / 三甲商业产品与合规基准 / 知识库许可），
> 结论区分「已核实」与「未核实」。**未克隆仓库实跑**——原因见 §4。

---

## 1. 核心结论

1. **没有任何现有开源 HIS 能直接承担中国三甲全院核心业务**。国内两个可用的 OpenHIS 版本在官方
   说明里明确只"适配一二级/二级以下"；国际项目（OpenMRS/Bahmni/OpenEMR/GNU Health）缺中国医保、
   物价、电子病历分级、互联互通与国密能力。
2. 三甲的现实形态是：**商业 HIS 作为院内主系统 + 院内集成平台 + 自建医保/EMPI/AI 中台**。
   开源的正确用法是**组件级复用 + 架构参考**，不是"fork 一个半成品当底座"。
3. 质量最优的可复用组件（均已核实许可）：
   - 影像：`dcm4chee-arc`（MPL-1.1）+ `OHIF`（MIT），或 `Orthanc`（GPLv3+，注意插件 AGPL）
   - 互操作：`HAPI FHIR`（Apache-2.0）；集成引擎 `Mirth/OIE`（MPL，4.6+ 转商业，需锁 4.5.x）
   - 分组：`OpenDRG`（Apache-2.0，CHS-DRG 1.0–3.0 + 地方分组器）
   - 数据模型参考：`OpenMRS`（MPL-2.0，Obs/Encounter/Order 与 omod 机制）、`openEHR/EHRBase`
     （Apache-2.0，archetype 版本化 + AQL）
4. **知识库不用"到处爬"**：有一份可核实的"最小合规组合"（见 §5），且必须避开 UpToDate、
   指南全文爬取、无许可对话数据集。

## 4. 为什么本轮没有"克隆跑起来"

- 候选项目在**等级定位**上已先出局（官方文档自述二级及以下），实跑只能证明"能启动"，
  无法改变"撑不了三甲"的结论，属于低价值验证。
- 唯一值得实跑的是 **OpenHIS 信创版**（Java17+Vue3），目的是核对其业务模块完整度与代码质量
  （是否只是 CRUD、是否有医嘱闭环状态机、是否有审计与并发设计）。**这一步需你点头后执行**，
  预计占用 10~20GB 磁盘，并需要 MySQL/PG/Redis。

## 5. 三甲能力基准（决定"不能少什么"）

**不可缺能力**：门诊/住院/急诊/护理/医嘱/病历/临床路径/手麻/输血/检验检查/药事/消毒供应；
EMPI + 主数据 + 术语字典 + 知识库 + CDR/ODR；集成平台（ESB/消息/共享文档）；多院区与集团化；
等保三级与容灾；病案首页/结算清单/DRG/DIP/单病种/HQMS；开放 API（HL7 v2/FHIR/REST）。

**合规硬指标（已核实）**：
- 电子病历分级 2018：5 级 20 基本项 + 6/19 选择项 / 140 分；6 级 21 项 / 170 分
- 互联互通 2020：五乙 = 四甲 + 共享文档 + 术语字典统一 + 上级平台交互 + 互联网诊疗 + CDS/闭环；
  知识库要求四甲 ≥2、五乙 ≥4
- 三级医院评审 2022：24 节 185 条，数据源为 HQMS/单病种
- 医保：**定点机构接口规范已到 V1.6**（此前文档写的 V1.0 需更正，实际以省局下发为准）；
  DRG/DIP 2.0 已切换；结算清单按国家统一编码
- 等保三级：审计留存 ≥6 个月、灾备、监测预警

**厂商架构参考（公开资料口径）**：卫宁 WiNEX"三中台" + WinDHP 开放平台 + WiNGPT；
东软 RealOne Suite 中台化；和仁 Java + K8s + ESB/EMPI/MDM + FHIR/HL7/IHE（对标四甲/五乙）；
东华 iMedical Cloud"大中台小前台"；创业慧康 Hi-HIS 微服务；嘉和 EMR + 数据中心；北大医信 XAP。

## 6. 知识库最小合规组合（已核实许可）

**可用（免授权/开放）**：卫健委诊疗方案与 224 个临床路径；三级医院评审标准与质控指标；
WS 445 / WS/T 500 / WS 363 / WS 364；ICD-10 临床版 2.0 与 ICD-9-CM-3 3.0（仅编码用途，
训练/再分发需法务确认）；医保药品目录 2025；DRG/DIP 2.0；结算清单规范；NMPA 说明书（在线检索）；
OpenKG 医疗图谱（CC BY）；MedlinePlus（公有领域）；PMC OA 子集（逐篇 CC）；USPSTF。

**需授权/仅科研**：CMeKG（CC BY-NC 4.0，商用不可）；CBLUE / PromptCBLUE（仅学术，禁商用）；
MedDG / cMedQA2（GPL-3.0，权重分发有传染风险）；WHO（CC BY-NC-SA）；NICE（境外 + AI 用途须付费）；
中华医学会系列 / 医脉通 / 丁香园 / 人卫社（须采购）。

**禁用**：UpToDate（条款禁止输入 AI/训练）；Toyhom 对话数据（无许可声明）；任何"指南全文爬取合集"。

**模型**：BGE-M3（MIT）、bge-reranker-v2-m3（Apache-2.0）、Qwen2.5 7B/14B/32B（Apache-2.0，
须完成算法备案）；Qwen2.5-72B 有 1 亿 MAU 门槛，GLM-4-9B 商用需登记。

## 7. 建议路线（质量优先）

| 路线 | 内容 | 质量上限 | 工程量 | 适用前提 |
|---|---|---|---|---|
| **R1（推荐）** | 院方商业 HIS 为主系统；我们交付集成平台 + EMPI + 医保适配 + AI 中台；影像/FHIR/DRG 用开源组件 | 高（临床核心由成熟厂商承担） | 中 | 医院已有或将采购 HIS |
| R2 | 以 OpenHIS 信创版为业务参考，自研核心 HIS（分模块渐进） | 中高（取决于投入） | 极大 | 有长期研发团队、要做产品 |
| R3 | 直接把 OpenHIS 当底座交付 | 低（定位一二级） | 中 | 仅二级及以下医院 |

> 结论：**三甲场景选 R1**；若要做产品化自研，走 R2，并且只把 OpenHIS 当"需求与交互参考"，
> 数据模型参考 OpenMRS/openEHR，不要继承其 GPL 代码结构。
