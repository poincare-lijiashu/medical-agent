# MedAssist 商用系统第三方评测方案（2026-11-13）

> 目的：对当前系统做一次**独立、只读、不修改代码**的商用就绪度评测，产出可复核的
> 分域报告与汇总报告，供后续整改与外部评审（含等保/密评/电子病历/互联互通）引用。

---

## 1. 评测方法论（业界主流框架的组合）

本方案不是自创标准，而是把以下公开标准/方法映射到本系统，按"证据优先"原则执行：

| 来源框架 | 用途 | 本方案取用的维度 |
|---|---|---|
| **ISO/IEC 25010:2023 (SQuaRE)** | 产品质量的九大特性，是业界最通用的"软件评什么"基线 | 功能适合性、性能效率、兼容性、易用性、可靠性、安全性、可维护性、便携性 + 安全性（Safety） |
| **ISO/IEC 25019 / GQM（Goal-Question-Metric）** | 把抽象质量目标翻译成可取证的问题与度量 | 每条结论必须落到"目标→问题→度量→证据"四层，禁止无证据打分 |
| **ISO/IEC 25020 / 25021** | 质量测量框架与质量报告 | 统一报告结构与评分刻度 |
| **OWASP ASVS 5.0（L1/L2/L3）** | 应用安全验证标准的分档要求 | 认证/会话/授权/输入校验/错误处理/加密/日志等章节逐条比对，目标 **L2 全覆盖、L3 关键项** |
| **OWASP WSTG v4.2** | 渗透测试方法与证据式报告 | 安全域按"发现项（含复现步骤、证据、影响、修复建议）"报告，不接受只有结论 |
| **SUS（System Usability Scale）+ Nielsen 启发式** | 易用性量化与启发式评审 | 前端/交互域给出 SUS 估算与启发式违规清单 |
| **DORA 5 项指标**（吞吐×2、不稳定×3） | 交付效能 | 用 Git 历史与发布台账估算 lead time、部署频次、变更失败率、恢复时长 |
| **IEC 62304 / ISO 14971 / YY/T 0664** | 医疗软件生命周期与风险管理 | 若系统按 SaMD 定位则适用；本系统定位为医院业务平台，映射为"临床安全闭环"维度 |
| **国家医疗健康信息互联互通标准化成熟度测评方案（2020 年版）** | 国内医院信息系统的官方分级 | 集成与数据维度按技术架构/数据资源/互联互通/数据质量四类评分项比对 |
| **电子病历系统应用水平分级评价（6 级）** | 国内 EMR 成熟度 | 临床闭环维度按"是否可追溯、是否有质控与签名"判定 |

### 1.1 评分刻度（0–5）

| 分 | 判定标准 | 证据要求 |
|---|---|---|
| 0 | 不存在/无任何实现 | 无 |
| 1 | 仅有设计文档、脚手架或 TODO | B 级（文档/空壳） |
| 2 | 部分实现，关键路径未闭环，存在明显断点 | B 级 |
| 3 | **达到主流基线（Parity）**：功能可用、路径闭环、有基本校验 | B 级 + 至少 1 处 A 级 |
| 4 | **优于基线**：有失败闭环、审计、度量或自动化门禁 | A 级证据 ≥2 处 |
| 5 | **超越项（Differentiator）**：可量化、可演示、有持续改进机制 | A 级证据 ≥3 处且含度量/趋势 |

### 1.2 证据等级

- **A 级**：可复现的运行证据——命令输出、真实接口响应、测试通过记录、浏览器实测结果、数据库真实查询结果；
- **B 级**：代码/迁移/测试/配置的存在性证据——文件路径 + 关键行号 + 实现要点；
- **C 级**：仅文档或注释声明（**不得作为打分的主要依据**，最多用于解释）。

### 1.3 打分纪律（本次评测的硬约束）

1. **只评测不修改**：不得修改任何产品代码、配置、迁移、构建产物；只允许在本目录写报告。
2. **结论必须可复核**：每条结论给出文件路径+行号，或可重跑的验证命令。
3. **不猜**：无法取证时写"无证据/未覆盖"，并计入"证据缺口"，不得按"应该有"给分。
4. **区分软件缺口与外部依赖**：等保/密评/CA/医保联调等需第三方或院方完成的事项，
   归入"外部项"，不计为软件失分，但必须在报告中显式列出。
5. **给可执行结论**：每个失分点必须给出"最小整改动作"，便于后续排期。

## 3. 分批执行计划（最多 2 个并发子智能体）

| 批次 | 并发评测域 | 产物 |
|---|---|---|
| 批次 1 | E1 架构与可维护性 ‖ E2 功能与临床闭环 | `01-architecture.md`、`02-functional-clinical.md` |
| 批次 2 | E3 安全与合规 ‖ E4 可靠性与性能 | `03-security-compliance.md`、`04-reliability-performance.md` |
| 批次 3 | E5 数据治理与互操作 ‖ E6 AI 验证与治理 | `05-data-governance-interop.md`、`06-ai-governance.md` |
| 批次 4 | E7 测试与质量工程 ‖ E8 交付运维与产品化 | `07-test-quality-engineering.md`、`08-delivery-ops-product.md` |
| 汇总 | 汇总编制 | `SUMMARY.md`（总分、分域雷达、Top 缺陷、整改优先级、外部项清单） |

**容错纪律**：每个子智能体把报告**直接写盘**到指定文件后即结束（不依赖主进程回传）；
某个子智能体失败不影响同批其它子智能体，汇总阶段只收录已落盘的有效报告，缺失域在
汇总中标注"未完成"，绝不臆造。
