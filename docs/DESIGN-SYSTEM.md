# 铭医 MedAssist · 设计系统 v3「临床台账 / Clinical Ledger」

> 适用：`frontend-console/`（对接 `/api/v2` 的临床控制台）。
> 目标不是"好看"，而是**安静、可信、可核对**：医护连续工作 8 小时，界面不能抢注意力，
> 每个数字都要能回答"谁做的、什么时候、依据什么"。

v3 的改动不是换一套颜色，而是换一套**信息组织方式**：从"卡片后台"改为**台账 + 仪表**。
页面像一张被校准过的临床记录纸：有编号、有刻度、有发丝线、有手写体量的数字。

> 依据：`docs/skills-audit/ORIGINAL-20.md`（20 个技能原文）与 `docs/skills-audit/DEDUPED.md`
> （去重版）。原始文件保持逐字不动；本文件只记录提炼后的规则与取舍。

---

## 0. 三条不妥协

1. **数字优先。** 关键读数用等宽字体、右对齐、单位降级；读数的视觉重量高于标题。
2. **证据随身。** 数据来源、更新时间、口径、权限边界（或"由服务端裁决"）与操作同屏。
3. **安静。** 强调色只花在数据与可操作对象上；其余是纸、墨、线。

## 1. 十二条可执行规则

提炼自 `docs/skills-audit/raw/` 中的 taste-skill v2.1、Impeccable、frontend-ui-engineering、
web-design-guidelines。每条都必须能在代码里指到落点。

| # | 规则 | 落点 |
|---|---|---|
| 1 | 每页只有一个视觉主角（通常是数据面或时间轴），其余降级为辅助 | 手术排台：时间轴；医嘱：医嘱明细 |
| 2 | 一屏内按钮尺寸不超过两种（31px 默认 / 26px 紧凑） | `.btn`、`.btn--sm` |
| 3 | 层次用 1px 发丝线与留白，不用大阴影、不用玻璃拟态 | `--line`、`.sheet`、`--shadow-card` |
| 4 | 强调色占比 ≤ 10%，只给主操作、当前选中、焦点环、关键数据 | `--accent` 使用清单 |
| 5 | 状态永远"点 + 文字"，不能只靠颜色 | `StatusPill` |
| 6 | 数字等宽且右对齐；金额只展示，不在前端做计费运算 | `.readout`、`.is-num` |
| 7 | 真实数据可视化：无数据就显示空态，不画假曲线 | `TrendChart`、`EmptyState` |
| 8 | 表格超过 9 列拆到检查器；行高 34–40px，表头等宽小字 | `.table`、`.sheet-inspector` |
| 9 | 三档宽度自检：1440 / 1728 / 1024；每档只允许一种主布局 | `.board`、`.sheet-grid` |
| 10 | 键盘全流程可达；焦点环 2px 白 + 2px 蓝；弹层焦点陷阱 | `--focus`、`AppModal` |
| 11 | 动效只解释因果，120–260ms，尊重 `prefers-reduced-motion` | `--dur*`、`.page-enter` |
| 12 | 每轮只修最严重的 3 个问题，修完再截图复验 | 本文档「验收」一节 |

## 2. 视觉语言

### 2.1 纸与墨

浅色为默认（诊室明亮、长文密集）。暖白纸底而不是冷灰，减少屏幕塑料感；
深色主题是"夜间手术室"，不是简单反色。

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--bg` | `#EFEDE7` | `#0C0E11` | 页面纸底 |
| `--panel` | `#FBFAF7` | `#13161A` | 数据纸面 |
| `--panel-2` | `#F6F4EE` | `#171A1F` | 表头 / 检查器 |
| `--sunken` | `#E8E5DC` | `#0F1216` | 下沉区 / 分段控件 |
| `--line` | `#DFDBD1` | `#262A30` | 发丝线 |
| `--line-strong` | `#C8C2B4` | `#363C44` | 容器边界 |
| `--ink` | `#16181C` | `#ECEAE4` | 主墨 |
| `--ink-3` | `#6A6F77` | `#8D918F` | 辅助文字 |
| `--accent` | `#1F4BD8` | `#7F9CF7` | 印刷群青：选中 / 数据 / 链接 |
| `--ok` / `--warn` / `--danger` | `#1B6B4A` / `#86590C` / `#A32B22` | 对应提亮 | 状态 |

### 2.2 书脊

左侧导航是**深石墨书脊**（`--rail: #14171C`），与纸面形成装订关系：

- 分组编号 `01 / 02 / 03`，等宽小字；
- 当前项：2px 群青左标记 + 提亮背景 + 端点；
- 底部固定：命令入口、用户与角色；不做假"系统正常"角标。

### 2.3 刻度与编号

- 页头底部有 4px 刻度带（`repeating-linear-gradient`），像裁切线，不是装饰花纹。
- 页头左侧大号编号（`03`）标示页面在信息架构中的位置。
- 分区标题：`编号 + 名称 + 贯穿细线`（`.section-head`）。

### 2.4 图像与图标

- 图标全部自绘：24×24 网格、1.5px 描边、圆角端点；`AppIcon` 覆盖 **80+** 字形，
  包括手术间、术式、麻精、病案、药片、麻醉机等医疗语义。
- 品牌标记：深石墨圆角方块 + 白色脉搏 + 群青端点（`public/brand/mark.svg`）。
- 空态插图：诊疗单 / 盾牌 / 知识卡片三张线稿，使用纸色、发丝线与单一群青，
  随主题换色、可打印、零外部依赖。
- 登录仪表板：手写 SVG 刻度盘 + 手术间时间轴 + 脉搏线；不使用照片与生图占位。

## 3. 字体与字阶

- 拉丁与数字：`IBM Plex Sans Variable`；中文回退 `PingFang SC / Microsoft YaHei / Noto Sans CJK SC`。
- 等宽：`IBM Plex Mono`（400/500）。
- 字阶：9（微标签）/ 10（元信息）/ 11（控件）/ 12（正文）/ 14 / 16 / 20 / 24 / 28 / 32（页标题）/ 44（登录标题）。
- 关键读数：`.readout` = Plex Mono + `tabular-nums` + `-0.035em`，例如 KPI 的 `11.7%`。
- 表格表头与分区标签：等宽 9–10px + `letter-spacing: .12em`，全大写。
- 标题 `letter-spacing: -0.035em`，正文行高 1.7（说明）/ 1.58（常规）。

---

## 4. 间距、圆角、阴影、动效

- 间距：4pt 栅格（2 / 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64 / 80）。
- 圆角：2（徽标、输入）/ 3（按钮、面板）/ 5（浮层）。**不用 8px 以上的"圆润卡片"**。
- 阴影：只有浮层使用；纸面靠 1px 线与内高光。
- 动效：`--ease: cubic-bezier(.22,1,.36,1)`；页面进入 170ms 位移 4px；不使用弹跳。
- 层级：sticky 10 < rail 20 < backdrop 40 < modal 50 < toast 60 < tooltip 70。

## 5. 页面框架

所有页面共用同一"页框"，避免每页长得像不同产品：

```
PageMasthead
  编号 | KICKER + 标题 + 一句话职责            | 操作 / 事实栏
  ───────────────── 刻度带 ─────────────────
KPI 台账条（可选，4 格，全部真实数据）
工具条（筛选 + 主操作）
Sheet（数据面）
  └ 检查器（只读：口径、走势、选中对象）
```

- `PageMasthead`：`index / kicker / title / mandate / facts` + `actions` 插槽。
- `.kpi-strip`：四格连体台账，格间 1px 线，左缘 2px 状态条；数字 28px 等宽。
- `.sheet`：主数据面；`.sheet-head` 46px，`.sheet-grid` 支持右侧 320px 检查器。
- 检查器只读；编辑一律弹层并二次确认。

### 5.1 医嘱工作台

患者检索 → 患者上下文条 → KPI（医嘱 / 待执行 / 收费单 / 转送异常）→ 三栏
（就诊 / 医嘱主区 / 检查器）。金额、状态、可执行动作全部以服务端为准。

### 5.2 手术排台

- KPI：可用手术间 / 当日台次 / 当日利用率 / 接台间隙（来自 `/surgery/utilization`）。
- 左：按位置分组的手术间，含当日利用率与台次；
- 中：07:00–20:00 真实时间轴（按 `plannedStart/plannedEnd` 定位），当前时刻红线；
- 右：手术间档案 + 7 日利用率走势 + 选中台次（分级审批入口）。
- 首屏自动落到当天有台次的手术间。

## 6. 组件规范

| 组件 | 文件 | 约束 |
|---|---|---|
| 图标 | `components/ui/AppIcon.vue` | 自绘 80+；`label` 为空时 `aria-hidden` |
| 页头 | `components/ui/PageMasthead.vue` | 编号 / 标题 / 职责 / 事实栏 / 操作 |
| 走势图 | `components/ui/TrendChart.vue` | 纯 SVG；0 值保留基线；悬停给精确读数 |
| 弹层 | `components/ui/AppModal.vue` | ESC / 遮罩关闭；焦点进入；Tab 陷阱 |
| 状态徽标 | `components/ui/StatusPill.vue` | 状态码 → 中文 + 色点；未知状态显示原值 |
| 空态 | `components/ui/EmptyState.vue` | 必含"下一步做什么"；三张自绘插图 |
| 反馈 | `components/ui/ToastHost.vue` | `aria-live=polite`；错误 7s、成功 4.2s |
| 患者上下文 | `components/domain/PatientVisitSearch.vue` | 病案号精确 / 姓名模糊二选一 |
| 命令面板 | `components/ui/CommandPalette.vue` | ⌘/Ctrl+K；只列有权限的入口 |
| KPI | `components/ui/KpiCard.vue` | 指标 + 单位 + 事实说明；不得使用假数据 |

## 9. 运行与验收

```powershell
cd frontend-console
npm install
npm run dev          # http://localhost:5174（/api 代理到 127.0.0.1:8080）
npm run typecheck    # vue-tsc --noEmit，必须 0 错误
npm run build        # 产物 dist/（不入库，由 .gitignore 排除）
```

登录账号（dev）：`admin01 / Med@2026`。生产构建不含该提示（`import.meta.env.DEV` 控制）。

验收顺序：

1. 三档宽度（1440 / 1728 / 1024）逐页截图；
2. 控制台零 error / warn；
3. 键盘走完登录 → 搜索 → 选中 → 打开弹层 → ESC；
4. 每轮只修最严重的 3 个问题，最多 3 轮；
5. `typecheck` 与 `build` 通过后再提交。
