### 1.3 综合结论

> **加权完成度约 68%**（功能 90% / 工程 70% / 数据 60% / 前端 55% / 安全 55% / 运维 55%）。
>
> **这是一个"功能完备、可演示、可内部试用"的系统，还不是"可交付医院生产"的系统。**
>
> 差距不在功能数量，而在**三条生产底线**：①**数据可信**（双写已分叉、迁移缺域 → 换环境会静默丢数据）；
> ②**数据合规**（病例原文直送 LLM 并写审计、越权可读全院待核对条目、跨境管控可绕）；
> ③**交付可信**（CI 门禁管错对象、helm 门禁已红、无镜像构建断言）。
>
> 按下面 §3 的第一批（19 条 P0，约 15 人日）修完，完成度可提升到约 **80%**，届时才具备"院内试点"的资格；
> 完成 P1（46 条，约 40 人日）后达到"可交付医院生产"的水线。

## 二、系统真正的强项（必须承认并保持）

1. **架构护栏是可执行文档**，不是口号 —— `tests/test_architecture.py:54-79` 把依赖方向机械化为测试，`test_router_split_guard.py:135-147` 连路由**注册顺序**都做快照。
2. **降级设计克制且可观测** —— 熔断只统计连接类异常、stale 按域隔离 + 池就绪清 stale + 主动探测恢复（`pg_store.py:98-104/603-604/1242`）。
3. **生产事故直接写进代码注释** —— `pg_store.py:1346-1357` 的"骤缩拒绝"护栏记着"17 行账号被清成 1 行 → 全站 401"；`conftest.py:55-73` 记着假池断言漂移的根因。
4. **临床语义防呆严于一般商业系统** —— 双控（审核人≠提交人）、显式状态机 `_TRANSITIONS`（`prescriptions.py:32-37`）、"未提供院方阈值表 → 标记未启用，绝不臆造临床阈值"（`core/qc.py:89-110`）、PHI 脱敏收敛单点 `core/phi.py`。
5. **可观测性覆盖"业务静默失败"** —— 不只 CPU/内存，还有 PG 读/写/熔断/stale 探测、审计导出留痕。
6. **Helm values↔template 双向 0 缺失**（Python 脚本全量交叉引用验证）、渲染幂等（差异 0 行）、安全上下文三件套 11 个 Deployment 全覆盖。
7. **数据源真源意识强** —— PG 真源 + JSON 兜底 + "空表 → JSON 才是真源"的纪律贯穿全仓。

| 知识库可被任意 admin 上传内容直接进向量库并成为临床问答引用源，**无投毒防护与审核留痕** | kb 域 | 04 P1-4 |
| 知识库/文档解析**无进程隔离与超时**，恶意 PDF/图片可打满 CPU 或卡死进程 | kb_ingest | 04 P1-10 |
| **静态加密缺失**：病历、处方、影像、审计在磁盘与 PG 中均以明文存储 | 全域 | 04 P1-5 |
| 登录爆破无专用防护（通用 60/min 限流 + 无失败计数锁定） | auth 域 | 04 P1-6 |

| `.gitignore` 的 PHI 排除规则**不完整且不对称** | `.gitignore` | 04 P1-12 |

### 4.2 数据层与一致性（5 条）

- `count(*)` 空表探针在每次读路径做全表 Seq Scan（实测 0.204ms/1168 行，**O(N) 增长**）——02 P1-2
- 分页 count 与取数是两次独立往返，非同一快照，存在口径不一致 —— 02 P1-3
- Python 侧无版本化迁移目录，DDL 靠"幂等 ALTER 堆叠" —— 02 P1-5
- 全库 public schema **外键数 = 0** —— 02 P0-2（同源）
- `ix_audit_log_action_ts` 缺失（代码注释里"action 全为 null"前提已被回填脚本推翻，实测 null_action=0）—— 02

### 4.3 后端工程（5 条）

- `except Exception` **189 处**，"必要降级"与"掩盖故障"边界不清 —— 01 P1-5
- `asyncio.to_thread` 包裹同步桥，**线程池成为隐性瓶颈与死锁面** —— 01 P1-6
- `_arun` **无超时**，异步路径可无限期挂起主事件循环 —— 02 P1-5
- 私有符号跨模块引用，破坏封装边界 —— 01 P1-7
- 分页/过滤/聚合逻辑在 API 层与域层**双份实现**，语义靠注释维持一致 —— 01 P1-8

### 4.4 前端（6 条）

- 状态管理是"Pinia 三 store + 视图内 ref 各自为政"，跨视图共享靠直接改 store 字段 —— 03 P1-3
- 角标轮询无可见性感知，60s 固定轮询在后台标签页也照跑 —— 03 P1-2
- **长列表无虚拟滚动**；病例库/字典/规则是全量拉取 + 前端过滤 —— 03 P1-6
- 键盘可达性只在一个视图达标；表格/对话框/自定义控件普遍不达标 —— 03 P1-5
- **前端无组件级单测**，全部靠"静态标记锁 + 人工浏览器" —— 03 P1-11
- 403 处内联样式 + 无响应式 + 首屏 1.3MB（详见 D6）—— 03 P2

### 4.5 测试与 CI（12 条）

- 全量 pytest 5.5 分钟是"本地全跑"，CI 与本地职责未分离，CI 重复消耗在低价值环节 —— 05 P1-4
- 依赖供应链：无 lock 级锁定、无 CVE 扫描、npm 侧全为 `^` 范围 —— 05 P1-10
- 测试隔离缺口：`consults`/`prescriptions`/`case_archive` 未纳入 autouse 兜底 —— 05 P1-2
- 台账 377KB 单文件不可检索；`check_docs.ps1`/`refresh_baseline.ps1` 被文档引用但**不存在** —— 05 P1-7
- 发布与变更管理：版本号散落四处、无 CHANGELOG、无 release 产物清单 —— 05 P1-8
- settings 新增字段与 Helm values 无同步机制（**已发现 1 处实际漂移**）—— 05 P1-9
- 覆盖率无分支门槛（88.2% 行覆盖但无 branch coverage）—— 05 P1
- 全域零巡检，一致性完全依赖人工跑脚本 —— 02 P1-1

### 4.6 部署与运维（8 条）

- **零条 Job / CronJob 失败告警** —— 备份失败、迁移失败、审计归档失败全部静默 —— 06 P1-1
- 审计归档 CronJob 缺 `timeZone`、缺 Pod 安全上下文、`date -d` 依赖 GNU date、默认 `emptyDir` 丢归档 —— 06 P1-2
- PG 连接池预算未核算：10 个 Java 服务 + AI 中台的池上限可显著超过 `max_connections` —— 06 P1-3
- 生产必需配置项缺 Helm 入口（`AUDIT_TIMEZONE`/`TRUSTED_PROXIES`/`PG_POOL_MAX`）—— 06 P1-4
- 迁移 Job 与业务 Deployment 共用 selector 标签，Service 会尝试选中迁移 Pod —— 06 P1-6
- `backup_repo.ps1` 无保留策略，本地已积压 **95 个 bundle / 1.59 GB** —— 06 P1-6
- LLM 供应商无跨厂商 fallback、无预算上限、无用量治理闭环 —— 06 P1-8
- 指标命名不符合 Prometheus 规范（`/metrics` 顶层族名与后缀错配）；无 SLO / 错误预算 —— 06 P1-5、P1-7
