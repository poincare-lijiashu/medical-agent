## 0. 一句话结论

20 个批次的**功能完成度高、验证数字诚实、提交纪律好**，但**安全边界与"声称已交付"的兑现度之间存在系统性缺口**：

## 2. 建议优化（Should）—— 86 条

完整 86 条见各分册报告；此处按主题归纳代表项（括号内为分册编号 + 原始编号）。

### 2.1 架构与可维护性（18 条）
统一提示装配口径消除三处重复（01-S1/S3）；目录里 `kb` 与 `router` 智能体无路由关键词、永远不可达（01-S2）；上限常量在 5 个模块重复硬编码（01-S3）；死代码：两个模块的 `_save` 从未被调用（01-S10）；经验库"已审核"只是自述、无独立审核人（01-S11）；同一问题模式可被重复提炼成候选（01-S12）；PHI 正则三处复制粘贴易漂移（01-S14）；`/a2a` 端点不受 `agent_a2a` 开关约束、与 `/card` 行为不一致（01-S16）；Bot 绑定 `default` provider 时创建/审核期不校验模型合规（01-S17）；`/a2a` 请求体无 schema 校验、类型异常会 500（01-S18）；`consult_metrics.prometheus_text()` 同时暴露在两个端点，双目标抓取会重复计数（01-S6）。

### 2.2 指标语义与告警（17 条）
缺"target down/抓取失败""token 成本""回答质量"三类关键告警（02-S1）；`for` 时长与 `evaluation_interval` 未对齐，`for: 10m` 配 `rate[10m]` 实际响应约 20 分钟（02-S2）；counter 归零语义需在多副本聚合下明示（02-S3）；持久化快照与实时进程内计数放在同一面板但窗口语义未区分（02-S4）；`REPLAY_PASS_RATE_DROP` 比较对象是快照列表相邻两条但排序键只有 date（02-S8）；聚合 gauge 缺 `by` 维度、无法定位到具体能力域（02-S11）；`__other__` 归并让标签溢出不可观测（02-S12）；耗时 sum/count 分两个指标族暴露（02-S13）；前端看板把进程内计数与持久化指标同页，且错误率阈值与 Prometheus 规则**未对齐**（02-S14）；`usageShare` 分母是成功问答数、数值可 >1、命名误导（01-S5）；使用率看板把"无数据"显示成"使用率 0%"（01-S7）。

### 2.3 API 契约（16 条）
