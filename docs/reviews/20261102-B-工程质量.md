### [B-P0-01] 日期切换竞态：旧日期的排台响应覆盖新日期
- **位置**：`frontend-console/src/views/SurgeryBoardView.vue:L350-L393`（`loadDay`）、`L475-L483`（`applyDay`）
- **证据**：
  - `applyDay()` 只做 `day.value = next` + `void loadAll()`，`loadDay()` 内用 `day.value` 发起 N 个请求，`await Promise.all` 后**无条件**写 `roomUtilizations.value` / `utilByRoom.value` / `schedulesByRoom.value`（L364-L382）。

- **影响**：连续点「前一天/后一天」或直接改日期时，后发的请求先回、先发的请求后回，界面标题是 3 日、表格和利用率是 2 日。手术排台用于判断手术间占用，错位会直接导致加台/停台误判。
- **建议改法**：在 `SurgeryBoardView` 增加 `let loadSeq = 0`；`loadDay()` 开头 `const seq = ++loadSeq; const target = day.value`，所有 `await` 之后 `if (seq !== loadSeq || target !== day.value) return` 再写状态。或给 `surgeryApi.roomSchedules/roomUtilization` 增加 `signal` 参数并在 `applyDay` 中 `controller.abort()`。

### [B-P0-02] 切换就诊竞态：上一就诊的医嘱显示在新就诊表头下
- **位置**：`frontend-console/src/views/OrdersWorkbenchView.vue:L811-L814`（`pickVisit`）、`L931-L942`（`loadOrders`）、`L1046-L1053`（`loadCharge`）
- **证据**：`pickVisit` 只改 `selectedVisit`，随后 `Promise.all([loadOrders(), loadCharge()])` 内部直接 `orders.value = await ...` / `charge.value = await ...`，没有任何请求身份校验；`loadVisits`（L794-L809）也复用同一路径。
- **影响**：在左侧连续点两次不同就诊（或换患者），旧就诊的医嘱/金额可能最后返回并写入 `orders`/`charge`，而页面头部显示的是新就诊号与患者。医嘱与费用都是按就诊记账，串台会造成错账与错误处置。

- **验收方式**：后端对就诊 A 的 `/orders` 注入 2s 延迟，先点 A 再点 B，最终表格的 `visitId` 与表头一致（可在 Network 面板核对返回顺序与渲染结果）。

### [B-P0-03] 术前访视切换病例竞态：A 的评估被填进 B 的表单，并可能签署落库
- **位置**：`frontend-console/src/views/PreopVisitView.vue:L309-L322`（`selectCase`）、`L291-L307`（`onSelect`）
- **证据**：`selectCase` 先 `current.value = c`，再 `record.value = await surgeryApi.preopVisit(c.id)`，成功后**无条件** `fillForm(record.value)`；`fillForm` 直接覆盖 12 个表单字段（L275-L289）。`save()/sign()` 用的是 `current.value.id` + `form` 内容（L347-L374）。
- **影响**：快速点两个病例时，A 的 ASA 分级、禁食时长、气道评估、麻醉结论会显示在 B 的卡片下；此时点「签署访视单」，会把 A 的评估写进 B 的访视单（先 `savePreopVisit(B)` 再签发）。这是**临床安全级**的数据错位。

### [B-P0-04] 知识库跨空间竞态：上一空间的检索/问答结果展示在新空间下
- **位置**：`frontend-console/src/views/KnowledgeView.vue:L288-L294`（`selectSpace`）、`L315-L331`（`run`）
- **证据**：`selectSpace` 只清空 `searchResult/answerResult/query`；`run()` 用 `space.value.id` 发请求，`await` 后 `searchResult.value = ...` / `answerResult.value = ...` 无空间校验。`kbApi.answer` 的返回体包含原文引用 `quote`（`types.ts:L381`）。

### [B-P0-05] 收费单加载失败被伪装成"尚未生成收费单 / ¥0.00"
- **位置**：`frontend-console/src/views/OrdersWorkbenchView.vue:L1046-L1053`
- **证据**：
  ```ts

    if (!selectedVisit.value) return
    try { charge.value = await clinicalApi.charge(selectedVisit.value.id) }
    catch { charge.value = null }
  }
  ```

### [B-P0-07] 病案首页页签计数用"当前筛选结果"统计，切页签后其他状态恒为 0
- **位置**：`frontend-console/src/views/HomepageQcView.vue:L193-L196`（`countOf`）、`L198-L207`（按 `status` 拉取）、`L210-L213`
- **证据**：`setStatus(v)` 改 `status` 后 `load()` **只按该状态**请求 `emrApi.homepages(status, 100)`，`rows` 随即只剩该状态；而页签计数 `countOf(value)` 在 `rows.value` 上 `filter`。因此切到「草稿」后，「已提交」「已归档」两个数字变成 0。

### [B-P0-08] 会话失效只清本地状态，不跳登录页：页面继续展示旧患者数据
- **位置**：`frontend-console/src/api/http.ts:L108-L114`、`frontend-console/src/stores/session.ts:L89`、`frontend-console/src/router/index.ts:L36-L48`
- **证据**：401 分支 `if (!opts.publicRequest) onSessionExpired?.()`，而注册的 handler 是 `bindSession(() => clearSession())`（session.ts:L89）——只清 `state` 与 sessionStorage。路由守卫只在**导航时**执行；`AppShell` 的 `session.validate()` 失败也只 `return false`（session.ts:L131-L137），不跳转。
- **影响**：令牌过期/被踢下线后，当前页面仍显示该患者的姓名、病案号、医嘱与费用，后续操作全部 401。用户不会被告知"需要重新登录"，PHI 继续留在屏幕上（对共用工作站尤其危险）。
- **建议改法**：把跳转放进会话层：新增 `bindSessionExpired(handler)`，在 `router.isReady()` 之后注册 `() => { clearSession(); router.replace({ name: 'login', query: { redirect: router.currentRoute.value.fullPath } }) }`；或在 `AppShell` `watch(session.isLoggedIn, v => { if (!v) router.replace('/login') })`。

### [B-P0-09] 401 刷新重试无上限，存在递归请求风险
- **位置**：`frontend-console/src/api/http.ts:L80-L122`（尤其 L108-L114）
- **证据**：`if (res.status === 401) { if (!opts.publicRequest && (await doRefresh())) return once<T>(path, opts) }` —— 重试没有 `retried` 标记；`doRefresh()` 在 `refreshing` 归零后（L73-L75）每次都允许再次刷新。
- **影响**：若 `/auth/refresh` 持续返回 200 而业务接口持续 401（网关/时钟/用户被停用但 refresh 未联动撤销），会形成"401 → 刷新成功 → 重试 → 401"的无限递归请求，浏览器标签卡死并持续打网关；同时每次递归都会叠加调用栈。
- **建议改法**：`async function once<T>(path, opts, retried = false)`；401 分支改为 `if (!opts.publicRequest && !retried && (await doRefresh())) return once(path, opts, true)`；二次 401 直接 `onSessionExpired()` 并抛错。同时在 `doRefresh` 中记录失败次数，连续失败 2 次清空 refreshToken。
- **验收方式**：mock `refresh` 恒 200、业务接口恒 401，断言最多发出 `1 + 1` 次业务请求即抛 `ApiError(401)`，且 `onSessionExpired` 只触发一次。

### [B-P1-04] 时间口径两套：日期格式化固定 `Asia/Shanghai`，手术时间轴/访视输入用本机时区
- **位置**：`frontend-console/src/utils/format.ts:L10-L24` vs `frontend-console/src/utils/surgery.ts:L19-L32`、`frontend-console/src/views/PreopVisitView.vue:L261-L273`

- **影响**：在非 UTC+8 的终端（海外分会诊、跳板机、CI 截图、用户改了系统时区），列表日期是上海时间、排台时间轴按本地时间画：08:00 的台次可能画到 00:00，`now-line` 位置也随之错。排台与禁食时长判断都会偏。

## 8. 无障碍的代码层根因（非视觉）

1. **可点击 `<tr>` 无角色/无选中语义**：见 P1-17。`base.css:L658-L661` 已为 `tr[aria-selected='true']` 写好样式，但 `SurgeryBoardView` 只加 `.is-selected`，`aria-selected` 从未设置 → 设计意图与实现脱节。
2. **`:inert` 在 Vue 3 是生效的（已实测源码）**：`node_modules/@vue/shared/dist/shared.cjs.js:L342` 的 `specialBooleanAttrs` 包含 `inert`；Vue 对 `true` 写空属性、对 `null/undefined/false` 移除属性。`AppShell.vue:L11` `:inert="isMobile && !mobileOpen ? true : undefined"` 语义正确，**无需修改**；但它与 `aria-hidden`（L12）重复，可只留 `inert`（inert 已隐含对 AT 隐藏与焦点隔离）。
3. **`aria-*` 未被组件吞掉**：`StatusPill/PageHeader/KpiCard/EmptyState` 都是单根节点且未 `inheritAttrs:false`，透传属性会落到根元素，正常；`AppIcon` 显式绑定 `aria-hidden/role/aria-label`（L169-L171），外部再传 `aria-label` 时与 `label` prop 冲突，建议文档化为"语义图标必须用 `label` prop"。
4. **弹窗/面板焦点**：见 P2-09（ESC 作用域、关闭后不还焦、命令面板无陷阱）。
5. **表单标签**：`LoginView` 做得完整（`for/id` + `aria-invalid` + `aria-describedby`）；`OrdersWorkbenchView` 的目录搜索框（L554-L560）与 `KnowledgeView` 的查询 `textarea`（L105-L111）只有 `placeholder`，无 `aria-label`/`<label>` → 读屏只报"编辑框"。
