# 智能开药 & 商用化 · 路线图（2026-09-10 拍板）

> 决策记录：预填为真 bug；药品数据 AI 生成初稿+免责声明；两药快查从前端移除（降级为开药前置规则库）；病例库=合规留存（无相似检索）；外网已开可扩知识库；商用去 demo。稳中求进，逐阶段验收。

## 阶段 0 · Bug 修
- 0.1 重提预填真实修复（meta→各栏结构化直填，字段对齐 QcReq）——验收：点重提各栏有真实值
- 0.2 my_rejections 过滤只留 qc 类；drug 驳回跳药物助手预填

## 阶段 1 · 药品字典 + 数据扩容
- 1.1 PG drug_dict（规范名/别名/商品名/类别/等级）+ drug_rules（药对/严重度/机制建议/来源）+ repo（PG 真源 JSON 兜底）
- 1.2 数据生成：常用药 ~300 种（12 类含别名商品名）+ 相互作用规则 ~300 条（高危~80/中危~220）
- 1.3 medical_drug.py 读字典表（内存缓存），硬编码作种子迁移
- 1.4 免责声明三处（开药工作台/字典管理页/DEPLOY）：药品数据 AI 辅助生成，临床使用前必须经执业药师核对；仅供辅助决策不构成医疗建议
- 1.5 admin 字典管理页（pharmacist+admin，变更审计）

## 阶段 2 · 智能开药后端
- 2.1 prescriptions 表 + 状态机 draft→pending_pharm→approved/rejected
- 2.2 开药建议生成：字典候选池注入 prompt（LLM 仅字典内推荐，幻觉=0）+ 规则硬校验（高危阻断必填联用理由/中危警示）
- 2.3 提交/药剂科审核端点（一票+双控+驳回重写）
- 2.4 审计全程（含 forced_with_reason）

## 阶段 3 · 开药前端
- 3.1 开药工作台（取代药物助手导航位）：病例→推荐勾选→自定义加药→警示面板→提交
- 3.2 药剂科开药审核队列 + 通过/驳回
- 3.3 我的处方（状态+驳回意见+重写）；两药快查降级为工作台侧栏（独立导航删除）

## 阶段 4 · 病例库合规归档

- 4.2 病例库视图（qc/admin 筛选；医生本人记录）
