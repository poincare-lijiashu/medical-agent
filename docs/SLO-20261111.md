# 服务等级目标（SLO）与错误预算策略

> 版本：2026-11-11（第 268 批）
> 适用范围：网关、认证、临床核心、药事/医技、AI 中台、集成通道
> 关联：`docs/COMMERCIAL-READINESS-100-PLAN.md` §5.1、`docs/CAPACITY-MODEL-20261111.md`、
> `deploy/observability/alerts/medassist-alerts.yaml`（`medassist.slo` 组）

## 一、定义与口径

| 术语 | 定义 |
|---|---|
| SLI | 可测量的服务质量指标（成功率、延迟分位、限流比例） |
| SLO | SLI 在统计窗口内的目标值（本文件按自然月 + 30 天滚动双口径） |
| 错误预算 | `1 - SLO` 对应的允许失败量；例如 99.95% 月度预算 = 21.6 分钟不可用 |
| 快烧 | 短窗口（5m/1h）燃烧速度 ≥ 14.4 倍预算，提示正在快速耗尽 |
| 慢烧 | 中窗口（30m/6h）燃烧速度 ≥ 6 倍预算，提示持续劣化 |

**统一口径（避免"指标好看但口径不对"）：**

1. 可用性 `SLI = 1 - 5xx / 全部服务端请求`。**4xx 是客户端错误，不计入不可用**；
   401/403 单独作为安全指标，不与可用性混算。
2. **429 不计入可用性**：限流是保护动作，不是服务不可用；单独用 `gateway-throttle`
   SLI 观察是否已影响业务。
3. 延迟只统计**成功请求**（`status!~"5.."`），避免 5xx 快速失败把 P95 拉低。
4. 计划内维护窗口（提前 24h 公告、≤30 分钟/月）在月度报表中单列，**不豁免**预算，
   避免用"维护"掩盖稳定性问题；如院方要求豁免，需信息科与临床联合签字。
5. 统计以 Prometheus 抓取的 `http_server_requests_seconds_*` 为准；业务侧埋点
   （登录、限流、集成死信）作为补充证据。

| SLO-GW-AVAIL | 网关 | 1 - 5xx / 全部请求 | **99.95%** / 月 | 快烧 14.4x（5m/1h）、慢烧 6x（30m/6h） |
| SLO-AUTH-AVAIL | 认证 | 1 - 5xx / 全部请求 | **99.95%** / 月 | 快烧 14.4x（5m/1h） |

| SLO-CLIN-WRITE-LAT | 临床核心（写） | 非 GET 成功请求 P95 | **< 1s** | 写 P95 > 1s（沿用既有 P99/慢查询告警） |

### PromQL 参考

```promql
# 网关可用性（5m 快烧 > 14.4x 预算）
sum(rate(http_server_requests_seconds_count{component="gateway", status=~"5.."}[5m]))
/
clamp_min(sum(rate(http_server_requests_seconds_count{component="gateway"}[5m])), 0.001)

# 临床读 P95（只统计成功请求）
histogram_quantile(0.95,
  sum by (le) (rate(http_server_requests_seconds_bucket{component="clinical", method="GET", status!~"5.."}[5m]))
)

# 临床写 P95
histogram_quantile(0.95,
  sum by (le) (rate(http_server_requests_seconds_bucket{component="clinical", method!="GET", status!~"5.."}[5m]))
)

# 网关限流比例
sum(rate(medassist_gateway_rate_limited_total[5m]))
/
clamp_min(sum(rate(http_server_requests_seconds_count{component="gateway"}[5m])), 0.001)
```

> 若 `component` 标签未按 ServiceMonitor relabel 注入，规则会无数据；部署前用
> `up{component=~"gateway|auth|clinical"}` 与 `http_server_requests_seconds_count`
> 在 Prometheus 控制台确认标签存在。

## 三、错误预算策略

月度预算按 SLO 自动计算（99.95% → 21.6 分钟；99.9% → 43.2 分钟；99.5% → 3.6 小时）。

| 预算剩余 | 状态 | 必须执行 |
|---|---|---|
| > 50% | 正常 | 正常发布；每周看一眼燃烧曲线 |
| 25%–50% | 关注 | 发布需附回滚方案；优先处理慢查询/依赖抖动 |
| 10%–25% | 收紧 | **冻结非紧急功能发布**；只允许修复、降级、扩容类变更 |
| < 10% | 紧急 | **变更冻结**（P0 故障修复除外）；72h 内完成故障复盘与改进项 |
| 已耗尽 | 超支 | 变更冻结 + 信息科/临床/厂商三方复盘；SLO 目标重新评审 |

**发布联动：**

- 快烧告警触发 → 自动暂停当前灰度批次（人工确认后回滚）；
- 同一 SLO 连续两周慢烧 → 进入可靠性专项，不得用"加机器"代替根因分析；
- 任何降级（关闭非核心功能）必须写入事件记录，并在恢复后 24h 内复盘。

## 四、统计与复盘

| 项目 | 规则 |
|---|---|
| 数据源 | Prometheus（30 天保留）+ 月度归档；业务指标来自各服务埋点 |
| 统计窗口 | 自然月（管理层报表）+ 30 天滚动（工程告警） |
| 报表 | 每月 1 日生成：各 SLO 达成率、预算剩余、Top 5 燃烧来源、未达标改进项 |
| 复盘 | 预算剩余 <25% 或单次不可用 >10 分钟：48h 内完成无责复盘 |
| 责任人 | 服务 Owner 对 SLO 负责；SRE 维护规则与报表；临床信息科参与目标评审 |
| 目标评审 | 每季度一次；新服务上线前必须先定义 SLI/SLO 与告警 |

## 五、当前基线（2026-11-11，开发环境）

来源：最新一次 `reports/perf/slo-capacity-*.md`（mixed，2/4/8 并发，10s/阶段）。

| 并发 | RPS | P50 | P95 | P99 | 5xx | 429 | 判定 |
|---|---|---|---|---|---|---|---|
| 2 | 63.2 | 4.0ms | 10.3ms | 20.9ms | 0 | 0 | PASS |
| 4 | 125.3 | 3.8ms | 10.9ms | 22.2ms | 0 | 0 | PASS |
| 8 | 252.6 | 3.7ms | 10.3ms | 21.8ms | 0 | 47（1.9%） | FAIL（限流） |

结论：

- 稳态读路径在开发机单实例约 **125 RPS** 内满足 P95 < 800ms 且无限流；
- 8 并发时达到 252 RPS，但 429 约 1.9%，说明**网关限流先于应用饱和**；
  生产不能只看"应用还能扛"，必须同步评估网关 QPS 配额；
- 冷启动探测显示重查询（运营洞察/审计/护理看板）在缓存未热时明显更慢，
  上线前应预热或把重查询与核心读路径隔离；
- 以上是读路径、同机压测、无 TLS/WAF 的数字，**不能直接作为生产容量承诺**。

## 六、当前差距与上线前必须补齐

1. **高可用**：SLO 99.95% 需要网关/认证/临床至少 2 副本 + 反亲和 + PDB + 数据库主备；
   开发环境单实例不能作为达标证据。
2. **真实入口**：生产 TLS/WAF/Ingress 会增加 RTT 与限流维度，需在准生产复测。
3. **写路径**：下单、收费、签名、发药未纳入本轮压测；需用一次性测试患者做写路径容量。
4. **AI 中台**：首包/完整响应依赖外部模型，需单独按 provider 维度统计并设置熔断。
5. **集成通道**：ACK/DEAD 指标需与真实 HIS/LIS/PACS 联调后校准。
6. **长稳**：本轮每阶段 10s；上线前至少 30 分钟 soak + 一次依赖故障演练。
