# 临床控制台设计（Clinical Console Design）

面向"连续使用 8 小时、操作不可逆、数字必须可追溯"的医疗工作台。
**审美目标不是惊艳，而是可信、精确、耐看；任何装饰都必须服务于核对与扫读。**

## 1. 决策优先级（冲突时自上而下）

1. 患者安全与任务完成：状态、金额、可执行动作不能含糊。
2. 可核对性：每个数字能追到来源、时间、操作者；界面不做本地乐观改写。
3. 可访问性与性能：键盘可达、对比度、减少动效、首屏可用。
4. 品牌与审美：在不破坏前三条的前提下追求独特性。
5. 表达欲：最后才考虑"惊艳"。

> 摘自 UICraft 的 decision priority，并叠加医疗场景的安全优先级。

## 2. 表面分类（先分类，再动手）

| 表面 | 规则 |
|---|---|
| 运营控制台 / 工作台（本项目主形态） | 密度优先、状态齐备、控件稳定；不做滚动叙事、不做入场编排 |
| 表单 / 弹层 | 错误内联、焦点管理、危险动作二次确认 |
| 登录 / 品牌页 | 允许一个"记忆点"（如仪表台视觉），但不得伪造实时数据 |
| 报表 / 打印 | 颜色可降级为黑白，状态必须带文字 |

**禁止**把营销页的构图（居中大标题、三卡并排、静态 bento）套到运营界面。

## 3. 本项目视觉立场：Clinical Instrument（临床仪表台）

- **材料**：纸白底 + 石墨墨色 + 单一钴蓝；元信息用等宽字（编码/时间/病案号），正文用无衬线。
- **层次**：靠 1px 发丝线、留白与背景层级（bg / panel / panel-3 / sunken），不靠大阴影。
- **数字**：等宽数字、右对齐、单位降级为 11px 灰字；金额只做展示，前端不运算。
- **状态**：点是辅助，文字是主体；不允许只靠颜色。
- **动效**：120–180ms，只动 transform/opacity；表达状态变化，不做入场秀。
- **禁忌**：渐变按钮/文字、玻璃拟态、彩色侧边条、emoji 当图标、装饰性编号、假数据 KPI。

## 4. 排版与网格（硬参数）

- 字体：`IBM Plex Sans Variable`（拉丁与数字）+ `PingFang SC / Microsoft YaHei`（中文）；
  编码与时间用 `IBM Plex Mono`。不再使用 Inter/Roboto/system-ui 作为主字体。
- 字号：10（微标签）/11（元信息）/12（控件）/13（正文）/15/18/20/24（页标题）/30（登录主标题）。
- 行高：紧凑 1.25，正文 1.55；标题 `text-wrap: balance`。
- 间距：4pt 栅格，允许 2px 光学微调；页面内边距 24–28px。
- 圆角：控件 6，卡片 8，浮层 10；徽标 5。
- 表格：表头 11px/500、行高约 38px、数字右对齐、列宽优先给"项目名"。

## 5. 组件契约

| 原语 | 规则 |
|---|---|
| Button | 高度 32（sm 26/lg 40）；一个视图只允许一个 primary；危险动作必须文案写清后果 |
| Input/Select | 32 高；聚焦用 1px accent + 1px 外环；错误态红边 + 内联文案；不阻止粘贴 |
| Segmented | 用于"互斥视图切换"（长期/临时、检索/问答），不用于多选 |
| Badge/Status | 点 + 文字 + 色调；未知状态显示原值，不猜 |
| Modal | `role=dialog`、焦点进入、Tab 循环、ESC/遮罩关闭；危险操作在 footer 右侧 |
| Drawer/Inspector | 只读上下文用 inspector（患者、费用、转送），编辑用 modal |
| Command Palette | ⌘/Ctrl+K；只列有权限的入口；键盘 ↑↓/Enter/ESC |
| Empty | 说明"下一步做什么"，不给"暂无数据" |
| Skeleton | 与最终内容同形，不用中央大转圈 |
| Toast | 仅非阻断反馈；错误不靠 toast 传达，用内联 + 可重试 |

## 6. 页面配方（本项目）

- **工作台**：页头（标题+事实条）→ 上下文条（患者检索）→ KPI 条（4 个真实指标）→ 三栏（列表 / 主区 / 检查器）。
- **列表页**：筛选条 + 状态统计 + 表格；行可键盘进入，危险操作在行尾。
- **表单页**：单列或两列，字段分组，底部固定操作区；只读/锁定要说明原因（如"仅已计划病例可填写"）。
- **知识类**：结果必须带引用与"降级原因"；拒答就明说拒答。

## 7. 反模板清单（出现即打回）

- 每个 section 上方一个小号大写 kicker（`§ 01` / `FEATURES`）当装饰。
- 三张等宽卡片 + 图标 + 一句话卖点的"伪仪表盘"。
- 无数据支撑的 KPI、涨跌箭头、闪烁的"实时"角标。
- 纯色块表达危急值；无 `aria-label` 的图标按钮。
- 悬浮阴影卡片套卡片；大面积圆角（>12px）与渐变。

- [ ] `npm run typecheck` 0 错误；`npm run build` 通过
- [ ] 键盘走完主流程；焦点环不被固定头部遮挡
- [ ] 空 / 加载 / 错误 / 无权限 四态齐备
- [ ] 数字等宽、金额右对齐；时间统一 Asia/Shanghai
- [ ] 状态不只靠颜色；危险动作二次确认且写清后果
- [ ] 控制台无 error/warn；无布局抖动与横向溢出
- [ ] 1440 / 1728 两档宽度下不塌；窄屏 inspector 折行有序
- [ ] `prefers-reduced-motion` 下动画关闭

## 9. 参考来源（只取方法，不复制视觉）

- `frontend-design`（Anthropic）：先定方向、拒绝通用 AI 审美。
- `UICraft`（Impeccable 衍生）：决策优先级、实现→验证→迭代的闭环。
- `stark:web-design`：表面分类、运营界面以密度与状态为先。
- `web-design-guidelines`（Vercel）：可访问性与交互硬规则。
- `shadcn`：原语与组合优先，禁止手写一次性控件。
